# 정량 성과 근거 기록

리뷰 결과나 CHANGELOG에 전후 수치, 백분율, 정확도, 처리량, 지연 시간처럼
**정량 성과를 주장할 때만** 이 문서를 읽는다. 숫자가 없는 변경에서는 읽지 않는다.

## 기록할 조건

다음을 모두 만족할 때 `docs-keeper`의 `evidence` 모드로 기록한다.

1. 변경 전과 변경 후가 같은 지표·단위다.
2. 측정 조건과 표본이 같거나 차이를 명시할 수 있다.
3. 실제 실행 결과, 평가표, 로그 중 하나가 근거로 존재한다.
4. 포트폴리오나 이후 의사결정에 다시 쓸 만한 실질적인 변화다.

조건을 만족하지 않으면 숫자를 만들지 않는다. 체감, 단일 우연 표본, 서로 다른
조건의 결과는 `추정` 또는 `비교 불가`로 표시하고 확정 성과로 기록하지 않는다.

## 계산

- 시간·지연·호출 수처럼 낮을수록 좋은 값: `(변경 전 - 변경 후) / 변경 전 × 100`
- 정확도·처리량처럼 높을수록 좋은 값: `(변경 후 - 변경 전) / 변경 전 × 100`
- 정확도처럼 퍼센트끼리 비교할 때는 **퍼센트포인트 변화**도 함께 적는다.
  예: 80%→90%는 `+10%p`, 상대 개선율은 `12.5%`다.
- 변경 전이 0이면 상대 개선율을 계산하지 말고 `계산 불가(기준값 0)`로 적는다.
- 반올림 자릿수를 명시하거나 원래 측정 정밀도를 유지한다.

## 보관

- 사람이 읽는 요약과 재현 조건은 Git에 포함되는 `evidence/METRICS.md`에 남긴다.
- 작은 원본 출력은 `evidence/raw/<날짜>-<짧은이름>-before|after.txt`에 남긴다.
- 큰 출력은 저장하지 않고 생성 명령과 핵심 결과의 해시·경로를 적는다.
- 비밀키, 토큰, 쿠키, 개인정보, `.env` 값은 원본에 포함하지 않는다.
- CHANGELOG 항목 끝에는 해당 METRICS 제목 또는 파일 경로를 연결한다.

Git 커밋은 측정 시점에 아직 없다면 `측정 당시 HEAD`를 기록하고, 커밋 뒤 최종
해시를 보완한다. 근거 파일을 만들기 위해 벤치마크를 다시 돌려 외부 API 호출·비용·
부작용을 일으키지 않는다. 기존 결과가 없으면 `원본 결과 없음`이라고 정직하게 적는다.
